# Edge Function: terapeuta-invitations

Handles therapist invitation and activation lifecycle: `invite`, `resend`, `revoke`, `deactivate`, and `reactivate` actions.
Runs with the Supabase service-role key (Auth Admin API) — never invoked directly from the client.

See the full architecture and API contract in
[`.docs/features/terapeutasModule/DevSpec.md`](../../../../.docs/features/terapeutasModule/DevSpec.md) §8.2.

---

## Required Supabase Auth configuration (per environment)

When deploying to a new environment (staging, production, etc.), the following setting
**must** be applied in the Supabase dashboard before the invitation flow is tested:

| Setting path                                                           | Key              | Value                       |
| ---------------------------------------------------------------------- | ---------------- | --------------------------- |
| Project Settings → Authentication → Email Auth → **Mailer OTP Expiry** | `mailer_otp_exp` | `604800` (seconds = 7 days) |

**Why 7 days?** This is the maximum TTL allowed by Supabase Auth and was chosen (DEC-20,
`DevSpec.md §16 #1`) to give therapists enough time to accept an invitation without
urgency. The admin can resend the invitation at any time — there is no cooldown.

> Without this setting, Supabase falls back to its default OTP expiry (24 hours).
> Invitations sent before the setting is applied will still expire at 24 h; only
> invitations generated after the change will use the new TTL.

## Email template (Supabase Auth dashboard)

**Decision (DEC-15):** the invitation email template is managed from the Supabase Auth dashboard,
not versioned in the repo. Path: **Project Settings → Authentication → Email Templates → "Invite user"**.

The placeholder `{{ .ConfirmationURL }}` is the magic link generated by Supabase Auth when
`auth.admin.inviteUserByEmail` is called. It must be present in the template body so that
the invitee receives a working link.

The `redirectTo` parameter of `inviteUserByEmail` (set in `index.ts`) must be the absolute
URL of the web console plus `/auth/update-password`. Example for production:
`https://<app-domain>/auth/update-password`.

## Environment variables

The function reads these environment variables at runtime. The first three are auto-injected
by the Supabase Edge Functions runtime; only `WEB_CONSOLE_URL` must be set manually.

| Variable                    | Source                                                                     | Description                                                                 |
| --------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `SUPABASE_URL`              | Auto-injected by Supabase runtime                                          | URL of the Supabase project                                                 |
| `SUPABASE_ANON_KEY`         | Auto-injected by Supabase runtime                                          | Anon/public key (used to call `is_admin` with the invoker's JWT)            |
| `SUPABASE_SERVICE_ROLE_KEY` | Auto-injected by Supabase runtime                                          | Service-role key for Auth Admin API operations (never commit to the repo)   |
| `WEB_CONSOLE_URL`           | Set manually: `supabase secrets set WEB_CONSOLE_URL=https://<your-domain>` | Absolute URL of the web console — used as `redirectTo` for invitation links |

> `SUPABASE_SERVICE_ROLE_KEY` is a built-in secret automatically available to every Edge
> Function in a Supabase project. It does **not** need to be set via `supabase secrets set`.
> It must **never** be placed in `.env.local` or `.env.example`.

# Deploy the function

## Edge Function pattern (first function in this repo)

This function establishes the project convention for Supabase Edge Functions:

- Entry point: `index.ts` — `Deno.serve`, method gate (POST-only), admin check, action dispatch.
- Handlers: `handlers/<action>.ts` — one file per action, each exported as `handle<Action>`.
- Shared lib: `lib/` — `auth.ts` (admin guard), `clients.ts` (user + admin Supabase clients), `response.ts` (JSON helper).
- Imports use `jsr:@supabase/supabase-js@2` (Deno JSR — not `npm:`).
- Admin check: reads `Authorization` header, creates a user-scoped client, calls `supabase.rpc('is_admin')`.
- No Jest tests — Edge Functions run on Deno. Validate via `supabase functions serve` + `curl`.

## Actions

| `action`     | Payload                                   | Effect                                                                                                                                                                                                                                                                                      |
| ------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `invite`     | `{ nombre: string, email: string }`       | Creates auth user, sets `profiles.rol_id = terapeuta`, inserts `terapeutas` row with `estado_id = pendiente`, sends invitation email via Resend. Falls back to `notificaciones_outbox` on email failure.                                                                                    |
| `resend`     | `{ terapeutaId: string }`                 | Regenerates the invitation link for a `pendiente` therapist and resends the email.                                                                                                                                                                                                          |
| `revoke`     | `{ terapeutaId: string }`                 | Validates `estado = pendiente`, then hard-deletes `terapeutas`, `profiles`, and the auth user.                                                                                                                                                                                              |
| `deactivate` | `{ terapeutaId: string, motivo: string }` | Guards against self-deactivation; invokes `deactivate_terapeuta` RPC (validates 0 active patients + motivo, sets estado `inactivo` — from then on `is_console_user()`/`is_admin()` are false for that user — and deletes the user's Auth sessions); then bans the auth user for ~100 years. |
| `reactivate` | `{ terapeutaId: string }`                 | Invokes `reactivate_terapeuta` RPC; then lifts the auth ban (`ban_duration: 'none'`).                                                                                                                                                                                                       |

All actions validate that the caller has the `admin` role (via the request JWT) before
executing. Unauthorized callers receive `403 { error: 'no_autorizado' }`.

### Error codes — `deactivate`

| Code                         | HTTP | Meaning                                                        |
| ---------------------------- | ---- | -------------------------------------------------------------- |
| `body_invalido`              | 400  | `terapeutaId` missing or not a string.                         |
| `motivo_requerido`           | 400  | `motivo` missing or blank.                                     |
| `no_puede_autodesactivarse`  | 400  | Caller is trying to deactivate their own account.              |
| `tiene_pacientes_activos`    | 400  | Terapeuta has active patients; includes `count` in the body.   |
| `deactivate_failed`          | 500  | Unexpected RPC error.                                          |
| `ban_failed_after_db_change` | 500  | RPC succeeded but auth ban failed (pathological — manual fix). |

### Error codes — `reactivate`

| Code                           | HTTP | Meaning                                                          |
| ------------------------------ | ---- | ---------------------------------------------------------------- |
| `body_invalido`                | 400  | `terapeutaId` missing or not a string.                           |
| `reactivate_failed`            | 500  | Unexpected RPC error.                                            |
| `unban_failed_after_db_change` | 500  | RPC succeeded but auth unban failed (pathological — manual fix). |

## Local development

```bash
supabase functions serve terapeuta-invitations --env-file .env.local
```

The function is invoked from the frontend via:

```ts
supabase.functions.invoke('terapeuta-invitations', {
  body: { action: 'invite', nombre: '...', email: '...' },
})
```
